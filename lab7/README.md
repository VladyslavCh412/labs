## Запуск на Windows

Відкрити PowerShell у папці `lab7`. Потрібний Python; перевірений Python 3.13.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe launch.py
```

Після запуску відкрити http://127.0.0.1:8000. Облікові дані manager, dispatcher, viewer створюються у `data/LOCAL_ACCOUNTS.txt`. До першого запуску файла немає. Для зупинки всіх процесів натиснути Ctrl+C у терміналі.

Різні лабораторні запускати по черзі: порти 8000/8101/8102 спільні. Папки .venv/ і data/ локальні та не входять до репозиторію.

## Права

| Роль | Можливості |
|---|---|
| manager | Читає дані; додає транспорт/водіїв; змінює статус і номер; планує рейси |
| dispatcher | Читає Fleet; створює маршрути і рейси; зміна Fleet відхиляється з 403 |
| viewer | Лише читання |
| trips-service / bridge | Внутрішні ідентичності, не облікові записи браузера |

Права перевіряє сам Fleet або Trips, навіть у прямому запиті на порт 8101/8102. Токен живе 15 хвилин. Якщо протермінувався, форма входу з’явиться знову. Вихід очищує токен у браузері, але не відкликає його серверно до exp.

## Перевірка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe verification/live_smoke.py
.\.venv\Scripts\python.exe verification/load_test.py --duration 3 --rows 5000 --levels 1,10,50,100,200
```

Load test є прямим HTTP-запитом до Trips, не вимірюванням повного браузерного шляху. Він створює тимчасові 5000 рейсів і сервери на вільних портах, а не змінює робочі БД. Після оптимізації p95 при 100 users у зафіксованому експерименті **470.193 мс**, при 200 - **996.308 мс**. Це короткий локальний експеримент; результат на іншому комп’ютері може змінитися. Не запускати кілька load/performance перевірок одночасно.

Повний конвеєр:

```powershell
.\.venv\Scripts\python.exe verification/pipeline.py
.\.venv\Scripts\python.exe verification/negative_pipeline.py
```

У pipeline 70 функціональних кейсів запускаються з domain coverage, потім один HTTP performance gate окремо без coverage. Поріг p95 500 мс узято з ЛР1. Якщо його перевищено, конвеєр навмисно падає: це сигнал перевірити середовище/зміни, а не причина видалити твердження. Зафіксований локальний gate: p95 405.547 мс, 850 запитів без помилок.

`negative_pipeline.py` копіює джерела у тимчасову папку, додає заборонений імпорт і запускає той самий gate. Очікує exit 1 та перевіряє незмінність оригіналу. Успіх самого демонстраційного скрипту означає, що порушення було правильно відхилене.

## GitHub Actions

`.github/workflows/architecture.yml` активний лише в **корені репозиторію**. Копія всередині `lab7/` не активується автоматично. У цьому репозиторії workflow вже розміщений у корені `.github/workflows/architecture.yml`; матриця запускає незалежні lab7 та lab8. Старі lab/lab3/lab4/lab5 збережено. Статус поточної публікації та запусків дивіться у вкладках Commits і Actions репозиторію.

## Дані та обмеження

- Fleet і Trips мають незалежні SQLite; Dashboard і bridge спілкуються через HTTP.
- Кеш Vehicle має TTL 30 с, інвалідацію після змін і живе окремо у кожному процесі.
- Подія VehicleStatusChanged транзакційна з outbox; event_id і version захищають проєкцію від повторів і старих подій.
- Локальний стенд прив’язаний тільки до 127.0.0.1. TLS/IdP, ротація, MFA, розподілений rate limit і захищений від адміністратора аудит ще не реалізовані.
- GPS, зовнішня картографія, адміністрування ролей і RTO/RPO не заявляються як завершені.
- Доменні start/complete у ЛР7 протестовані як чисті правила. Нові HTTP endpoints start/complete і міграція mileage не реалізовані.
- Не публікувати `data/`, `.venv/`, локальні JWT, SQLite та паролі. У переданих архівах цих файлів немає.

Результати перевірок генеруються у `verification/` після запуску та завантажуються як артефакти GitHub Actions; їх не комітять. Звіти й презентація передаються окремо та не зберігаються в репозиторії.

## Додаткова перевірка під час публікації

Перший GitHub Actions прогін ЛР7 показав HTTP p95 516.807 мс (поріг 500 мс); ЛР8 на іншому runner пройшла. Поріг не послаблено. У ЛР7/8 додано bounded single-flight cache сторінки Trips: ключ `(limit, offset, active)`, TTL 1 с, максимум 128 записів, повна інвалідація після успішного створення рейсу. Дані однакові для всіх дозволених ролей; перевірка JWT/RBAC виконується до кешу.

Три нові тести перевіряють TTL/місткість, один loader при конкурентному промаху та видимість створеного рейсу одразу після інвалідації. Поточний конвеєр містить 70 функціональних кейсів і 1 HTTP gate. Первинні PDF та зафіксовані раніше локальні журнали залишено як історичні результати підготовки; зміни після публікації описані в `lab8/docs/adr/ADR-010.md` і GitHub Actions.
