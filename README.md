## Запуск нової версії

Відкрити **одну** папку lab6, lab7 або lab8, запустити `СТАРТ_FleetFlow.bat` або `START.bat`. Потрібний Python; перевірено 3.13. Перший запуск створює віртуальне середовище, встановлює зафіксовані залежності та відкриває http://127.0.0.1:8000.

Унікальні логіни та паролі створюються у `data/LOCAL_ACCOUNTS.txt` після першого запуску. Ролі: manager, dispatcher, viewer. В архіві або Git немає робочих секретів чи паролів. Нові версії прив’язані лише до localhost; зовнішній deployment потребує TLS/IdP та інших заходів зі звіту.

Різні версії запускати по черзі: вони використовують порти 8000/8101/8102. Тести також запускати **з кореня конкретної лабораторної**, а не загальним pytest з кореня репозиторію, оскільки історичні проєкти мають однакові імена модулів.

## Перевірки

Workflow [architecture.yml](.github/workflows/architecture.yml) запускає окремі lab7 та lab8 на Python 3.13:

1. Статичні правила чистоти домену та відсутності циклів.
2. 70 функціональних кейсів із domain line coverage не менше 95% (зафіксовано 100%).
3. Окремий реальний HTTP gate: 100 користувачів, p95 не більше 500 мс, без coverage-інструментування.
4. Негативний експеримент: заборонений імпорт у тимчасовій копії має зупинити gate з exit 1; основний код не змінюється.

Разом 71 перевірка у ЛР7/8; у ЛР6 - 36 функціональних перевірок. Виміряний локальний load test: p95 470.193 мс при 100 користувачах і 996.308 мс при 200; це короткий експеримент на localhost, а не production SLA. Дані та журнали - verification/ відповідних проєктів. Поточний результат GitHub CI дивіться у [Actions](https://github.com/VladyslavCh412/labs/actions).
