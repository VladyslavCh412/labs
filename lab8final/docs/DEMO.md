# Как показать работу преподавателю

Запустите проект через F5 и откройте http://127.0.0.1:8000.
Для основного показа оставьте обычный режим без входа.

## Сценарий на 7–10 минут

1. **Объясните назначение.** «Это управление машинами, водителями, маршрутами
   и рейсами. Интерфейс — TypeScript, сервер — FastAPI, хранилища — SQLite».
2. **Автопарк → Додати авто.** Создайте доступную машину. ID и номер должны
   быть новыми, например demo-car-1 и BH4321AA.
3. **Додати водія.** Создайте водителя с новым ID, например demo-driver-1.
4. **Рейси та маршрути → Новий маршрут.** Укажите новый ID, пункты
   `Одеса, Київ` через запятую.
5. **Створити рейс.** Выберите машину, водителя и маршрут. Нажмите **Почати**.
   Покажите, что машина получила статус **У рейсі**.
6. Нажмите **Завершити**, укажите **25 км**. Покажите завершённый рейс,
   свободную машину и прибавленный пробег.
7. Измените статус свободной машины на **На ТО**. В **Дані та події**
   обновите сведения: покажите событие Fleet и копию статуса в Trips.
8. Нажмите **Зробити два читання і показати результат**. Покажите hits/misses.
   Если запись уже в кеше, оба чтения могут оказаться попаданиями.
9. Покажите C4-диаграммы, таблицу требований и результат тестов.

## Как показывать запросы

Откройте http://127.0.0.1:8101/docs для Fleet и
http://127.0.0.1:8102/docs для Trips.
Разверните запрос → Try it out → введите значения → Execute.

| Где | Запрос | Что подтверждает |
| --- | --- | --- |
| Оба сервиса | GET /health | Сервис работает. |
| Fleet | GET /vehicles | Машины сохранены в Fleet. |
| Fleet | GET /vehicles/{vehicle_id} | Статус и пробег выбранной машины. |
| Trips | GET /trips/{trip_id} | Текущее состояние рейса. |
| Trips | GET /snapshots/vehicles | Собственная копия статусов из Fleet. |
| Fleet | GET /cache/stats | Счётчики кеша. |

Для уже завершённого на 25 км рейса повторите
POST /trips/{trip_id}/complete с `{"distance_km":25}`.
Пробег не должен прибавиться повторно. Измените 25 на 26 — ожидается 409.
Передайте `{"distance_km":"abc"}` — ожидается 422.

## Безопасность отдельно от обычного интерфейса

Обычный режим специально открыт без входа. Для проверки ЛР6 остановите
серверы, откройте CMD-терминал в папке проекта и выполните:

```text
set FLEETFLOW_AUTH_REQUIRED=1
python run.py start
```

Этот режим проверяется через Swagger. Без токена GET /vehicles даст 401.
На http://127.0.0.1:8000/docs выполните POST /auth/token:
`{"username":"admin","password":"123123"}`.
Скопируйте access_token, в Fleet Swagger нажмите Authorize, вставьте
сам токен без кавычек и слова Bearer. Теперь чтение должно дать 200.
Для проверки 403 используйте токен viewer; его пароль находится в локальном
LOCAL_ACCOUNTS.txt. Viewer читает данные, но не меняет статус автомобиля.

Остановите серверы и верните обычный режим в том же CMD:

```text
set FLEETFLOW_AUTH_REQUIRED=0
python run.py start
```

## Где требования лабораторных

Полная карта: [REQUIREMENTS.md](REQUIREMENTS.md).
ЛР1 — контекст и ADR; ЛР2 — слои в Trips; ЛР3 — две службы и их контракты;
ЛР4 — routing/adapter/factory/observers; ЛР5 — миграции, кеш, события;
ЛР6 — JWT и измерения; ЛР7 — tests и checks; ЛР8 — документация и презентация.

Тесты без команды: Ctrl+Shift+P → Tasks: Run Task → FleetFlow: tests.
Полный прогон: FleetFlow: full architecture verification.
Сохранённые измерения называйте результатами предыдущего прогона.
Текущие результаты смотрите в выводе запущенной проверки.
