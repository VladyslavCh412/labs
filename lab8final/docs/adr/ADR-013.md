# ADR-013: Фронтенд на TypeScript зі строгою перевіркою

Дата: 2026-11-03. Статус: Прийнято. Доповнює ADR-002/012.

Контекст: користувач уточнив обов'язковий стек — TypeScript для фронтенду,
FastAPI + SQLite для бекенду. Поточна DOM-панель вже покриває сценарії;
зміна UI-фреймворку не потрібна для виконання цієї вимоги.

Альтернативи: переписати на React; перейменувати JS без типізації;
типізувати наявний DOM-застосунок і ввести реальну компіляцію TypeScript.
Обрано останнє: найменше змін поведінки й перевірювана вимога до мови.

Рішення: frontend/src/app.ts — вихідний код, strict/noEmitOnError,
DTO та стан панелі мають типи, API-клієнт використовує generics, DOM-події
й помилки звужуються перед доступом. npm lock фіксує TypeScript 7.0.2.
FastAPI віддає тільки frontend/build, а не src або node_modules.
root setup/start/test/verify та CI виконують збірку. Бекенд залишається
FastAPI + власна SQLite кожного сервісу.

Наслідки: помилки типів зупиняють збірку; потрібен Node.js для розробки.
Згенерований JS включено як runtime artifact; джерело істини — .ts.
Runtime-валідація бізнес-даних залишається у Pydantic на бекенді.
Умова перегляду: складніша навігація/компоненти — окремий ADR про фреймворк.
