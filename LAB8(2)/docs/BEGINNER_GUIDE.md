# Как понять проект с нуля

Представьте диспетчера автопарка. У него есть машины, водители и поездки.
FleetFlow помогает записывать эти сведения и следить за поездками.
Для первого знакомства достаточно создать и завершить один рейс в браузере.

## Пять слов, которые пригодятся

| Слово | Простое значение |
| --- | --- |
| Frontend | Всё, что пользователь видит и нажимает в браузере. |
| Backend | Программа, которая обрабатывает действия и сохраняет результат. |
| База данных | Упорядоченное хранилище. Здесь это файлы SQLite. |
| API | Доступные действия сервера: получить машины, создать рейс, сменить статус. |
| Сервис | Отдельно запущенная часть сервера со своей зоной ответственности. |

Fleet означает «автопарк»: этот сервис отвечает за машины и водителей.
Trips означает «поездки»: этот сервис отвечает за маршруты и рейсы.
Маршрут — список пунктов, например Одеса → Київ.
Рейс — конкретная поездка по маршруту, с выбранными машиной и водителем.

## Зачем вообще несколько папок

`frontend` — экран. `backend` — обработка действий. `data` — ваши записи.
`tests` — автоматическая проверка. `docs` — объяснения для человека.
`checks` — проверки требований к устройству проекта и измерение скорости.
`contracts` — договорённость двух сервисов о форме сообщений.

Не нужно читать всё подряд. Для начала откройте `frontend/index.html`,
`frontend/src/app.ts`, `backend/trips/api.py`, `backend/trips/use_cases.py`
и `backend/trips/domain.py`.

## Что происходит после нажатия «Створити рейс»

1. Вы выбираете машину, водителя и маршрут в форме браузера.
2. `app.ts` собирает значения и отправляет запрос на сервер.
3. `backend/api.py` видит, что запрос относится к Trips, и передаёт его туда.
4. `backend/trips/api.py` проверяет, что обязательные поля заполнены.
5. `use_cases.py` проверяет маршрут и обращается к Fleet за сведениями
   о доступности машины и допуске водителя.
6. `domain.py` описывает допустимые состояния рейса и его переходы.
7. `storage.py` сохраняет рейс и событие в `trips.sqlite`.
8. Сервер отвечает; TypeScript обновляет таблицу в браузере.

Это и есть разделение на слои: приём запроса → сценарий → правила → хранение.
HTTP-запрос — сообщение от одной программы другой. JSON — формат сообщения:
например `{"id":"trip-1","vehicle_id":"car-1"}`. Это только часть полей примера.

## Что происходит при начале и завершении

После «Почати» Trips проверяет переход состояния рейса и отправляет Fleet
команду занять машину. Она получает статус «У рейсі».
После «Завершити» машина освобождается, а её пробег увеличивается.
Сами записи машины меняет Fleet, потому что он владеет этими данными.

Если повторить завершение с той же дистанцией, пробег второй раз не прибавится.
Это называется идемпотентностью: повтор действия не создаёт повторный эффект.
Если повторить уже завершённую операцию с другой дистанцией, сервер сообщит
о конфликте.

## Что такое событие

Событие — сообщение о том, что уже произошло. Например, «машина ушла на ТО».
Fleet записывает сообщение в outbox — таблицу исходящих событий.
`event_bridge.py` доставляет его Trips. Trips обновляет свою копию статуса.
Это выполняется в фоне: небольшая задержка допустима.
Номер уже обработанного события запоминается, чтобы повтор не дал дубль.

`event_worker.py` отдельно читает события создания рейса в Trips и создаёт
локальные уведомления. Внешние SMS и письма он не отправляет.

## Что такое кеш

Кеш — короткоживущая сохранённая копия ответа. Если машину спрашивают дважды,
второй ответ можно взять из памяти вместо повторного чтения SQLite.
Fleet хранит такую копию до 30 секунд и сбрасывает её после изменения машины.
На странице «Дані та події» есть кнопка, показывающая счётчики попаданий.

## Что значат файлы внутри сервисов

| Файл | Как его понимать |
| --- | --- |
| `api.py` | Входная дверь: какие запросы принимаются и какие ответы возвращаются. |
| `domain.py` | Правила предметной области: что разрешено машине или рейсу. |
| `use_cases.py` | Порядок действий для создания, начала и завершения рейса. |
| `storage.py` | Чтение и запись SQLite. Слово repository в классах означает это хранилище. |
| `factory.py` | Собирает нужные объекты и передаёт их сценарию. |
| `fleet_client.py` | Связывается с Fleet по HTTP от имени Trips. |
| `fleet_adapter.py` | Превращает ответ Fleet в понятные для Trips значения. |
| `observers.py` | Вызывает подписчиков, которым нужно отреагировать на событие. |
| `migrations.py` и SQL | Постепенно обновляют структуру базы данных. |

Названия классов оставлены английскими, как принято в Python.
Назначение каждого исходного файла объяснено в [FILES.md](FILES.md).

## Зачем оставлены сложные на вид части

Задания требуют два сервиса, отдельные базы, слои, четыре паттерна,
обновление схемы, события и проверки архитектуры. Удаление этих частей
сломало бы соответствие лабораторным.

Четыре паттерна здесь — конкретные способы организовать код:
Strategy выбирает владельца запроса, Adapter переводит ответ Fleet,
Factory собирает зависимости, Observer вызывает обработчики события.

Документы с именем ADR объясняют, какое решение принято и почему.
C4-диаграммы показывают систему сначала целиком, затем подробнее.
В `docs/refactoring/before` лежат исторические примеры для сравнения ЛР4.
Они не запускаются и не подключены к приложению.

## Как понимать сообщения об ошибках API

200 — действие выполнено; 201 — новая запись создана.
401 — нужен действующий токен. 403 — токен есть, но прав недостаточно.
404 — запись или запрос не найдены. 409 — действие конфликтует с состоянием.
422 — неверные входные данные. 503 — нужный сервис недоступен.

Swagger — страница со списком запросов. На ней можно нажать Try it out,
вписать значения, нажать Execute и увидеть ответ сервера.
Сначала изучите обычный интерфейс, затем повторите те же действия в Swagger.
