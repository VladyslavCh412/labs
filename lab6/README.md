# FleetFlow - лабораторна робота 6

Варіант 12: управління автопарком та маршрутами. Продовження `C:/lab5` і репозиторію https://github.com/VladyslavCh412/labs . Код і звіти попередніх робіт не змінювалися.

## Запуск на Windows

1. Розпакувати архів повністю. Відкрити папку `lab6`.
2. Подвійний клік **СТАРТ_FleetFlow.bat** або **START.bat**. Потрібний встановлений Python; перевірений Python 3.13.
3. Перший запуск встановлює залежності, генерує локальні облікові записи і відкриває http://127.0.0.1:8000 .
4. Логіни та випадкові паролі знаходяться у **data/LOCAL_ACCOUNTS.txt**, який створиться після запуску. Відкрити файл звичайним Блокнотом. До запуску цього файла немає.
5. Увійти manager, dispatcher або viewer. Для зупинки всіх процесів натиснути Ctrl+C у вікні запуску.

Якщо зайняті порти 8000/8101/8102, зупинити попередній FleetFlow у його терміналі. Різні лабораторні запускаються по черзі.

Ручний запуск із кореня папки:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe launch.py
```

## Права

| Роль | Можливості |
|---|---|
| manager | Читає дані; додає транспорт/водіїв; змінює статус і номер; планує рейси |
| dispatcher | Читає Fleet; створює маршрути і рейси; зміна Fleet відхиляється з 403 |
| viewer | Лише читання |
| trips-service / bridge | Внутрішні ідентичності, не облікові записи браузера |

Права перевіряє сам Fleet або Trips, навіть у прямому запиті на порт 8101/8102. Токен живе 15 хвилин. Якщо протермінувався, форма входу з’явиться знову. Вихід очищує токен у браузері, але не відкликає його серверно до exp.

## Що є у цій роботі

JWT, Argon2id, RBAC на власниках ресурсів, аудит, захищена HTTP-доставка подій, SQL-сторінка рейсів і реальний load test. Набір містить 36 функціональних кейсів (26 попередніх, 9 security і 1 pagination).

Основний звіт: **Звіт_ЛР6.pdf**. Аналіз попередніх робіт: [lab8/docs/ANALYSIS.md](../lab8/docs/ANALYSIS.md). Первинні секрети та персональні робочі дані у комплект не входять.

## Перевірка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe verification/live_smoke.py
.\.venv\Scripts\python.exe verification/load_test.py --duration 3 --rows 5000 --levels 1,10,50,100,200
```

Load test є прямим HTTP-запитом до Trips, не вимірюванням повного браузерного шляху. Він створює тимчасові 5000 рейсів і сервери на вільних портах, а не змінює робочі БД. Після оптимізації p95 при 100 users у зафіксованому експерименті **470.193 мс**, при 200 - **996.308 мс**. Це короткий локальний експеримент; результат на іншому комп’ютері може змінитися. Не запускати кілька load/performance перевірок одночасно.

## Дані та обмеження

- Fleet і Trips мають незалежні SQLite; Dashboard і bridge спілкуються через HTTP.
- Кеш Vehicle має TTL 30 с, інвалідацію після змін і живе окремо у кожному процесі.
- Подія VehicleStatusChanged транзакційна з outbox; event_id і version захищають проєкцію від повторів і старих подій.
- Локальний стенд прив’язаний тільки до 127.0.0.1. TLS/IdP, ротація, MFA, розподілений rate limit і захищений від адміністратора аудит ще не реалізовані.
- GPS, зовнішня картографія, адміністрування ролей і RTO/RPO не заявляються як завершені.
- Доменні start/complete у ЛР7 протестовані як чисті правила. Нові HTTP endpoints start/complete і міграція mileage не реалізовані.
- Не публікувати `data/`, `.venv/`, локальні JWT, SQLite та паролі. У переданих архівах цих файлів немає.

Результати перевірок знаходяться у `verification/`. Нові PDF і презентація українською, відповідно до попередніх звітів.
