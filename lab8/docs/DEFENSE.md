# Демонстрація та відповіді для захисту

1. Запустити `СТАРТ_FleetFlow.bat`. Відкрити `data/LOCAL_ACCOUNTS.txt`, увійти manager. Показати автомобілі та створення рейсу.
2. Вийти та увійти dispatcher. Проба змінити статус автомобіля отримує HTTP 403; створення маршруту дозволене. Це рішення приймає Fleet, а не кнопка UI.
3. Показати `verification/live_smoke.json`: login, прямий і proxy-доступ без токена відхилено, Trips має власну службову ідентичність для Fleet, bridge доставляє подію.
4. Відкрити `verification/load_results.json` і таблицю звіту ЛР6. Однакові 5000 рейсів, ті самі HTTP-запити, прогріті клієнти, p50/p95, 100 і 200 користувачів.
5. `python verification/pipeline.py`: статичні правила, 67 функціональних перевірок, coverage, окремий performance gate.
6. `python verification/negative_pipeline.py`: реальне падіння gate на тимчасовій копії після забороненого import sqlite3. Після цього поточний код залишається справним.
7. PPTX містить 10 слайдів і нотатки доповідача на приблизно 9.5 хвилини.

## Короткі відповіді

- **Чому права у сервісах?** Прямий порт обходить gateway; власник сутності має відхилити запит сам.
- **JWT шифрує дані?** Ні. Він підписаний; не класти в claims пароль або персональні дані.
- **Що перевіряється?** Алгоритм, підпис, exp, iss, aud та обов’язкові claims, потім роль.
- **Чи logout відкликає викрадений токен?** Ні, лише очищує пам’ять браузера; до exp потрібно denylist/IdP для реального відзиву.
- **Навіщо дві метрики latency?** p50 описує звичайний запит, p95 виявляє затримки хвоста, які середнє приховує.
- **Що було bottleneck?** Повний SELECT і Python-проєкція всієї таблиці для 50 рядків; Server-Timing вимірює repository, не вгадує CPU.
- **Чи доводить три секунди SLA?** Ні. Це відтворюваний локальний regression/load smoke, потрібен тривалий soak і deployment-профіль.
- **Чим contract test кращий за читання YAML?** Він незалежно виконує реальний provider і client із зафіксованими очікуваннями consumer.
- **Що означає 100% coverage?** Усі рядки двох domain.py виконані; це не всі комбінації та не весь застосунок.
- **Чому API не має спільної БД?** Кожен контекст є єдиним джерелом істини; зв’язок - HTTP або подія.
- **Чи C4 L3 показує всю систему?** Ні, компоненти одного обраного складного контейнера Trips.
- **Чому старий ADR не переписаний?** Щоб зберегти контекст. Заміна зазначається в новому записі та індексі.
- **Найважливіший борг?** TLS/IdP і backup перед зовнішнім deployment; обмежене SQL-читання не вирішує конкурентний запис чи GPS.
